# CLI

The Konet CLI is a single Go binary that manages the lifecycle of the Konet Server container.

## Installation

macOS and Linux, with Homebrew:

```bash
brew install raucheacho/tap/konet
```

Windows, with Scoop:

```powershell
scoop bucket add raucheacho https://github.com/raucheacho/scoop-bucket
scoop install konet
```

Linux without Homebrew, or a CI image — the install script downloads the
release archive for your platform, verifies its checksum and installs the
binary in `~/.local/bin`:

```bash
curl -fsSL https://raw.githubusercontent.com/raucheacho/konet/main/install.sh | sh
```

| Variable | Purpose |
|----------|---------|
| `KONET_INSTALL_DIR` | Where to put the binary (default `~/.local/bin`) |
| `KONET_VERSION` | Version to install, e.g. `v0.6.0` (default: latest) |
| `KONET_SKIP_CHECKSUM` | `1` to install without verifying the archive. Without it, an archive that cannot be verified — no checksums file, no entry for it, no sha256 tool — is refused |

The script refuses to run when Homebrew or Scoop already manages `konet`.

Every release archive also carries a build provenance attestation, so you can
check it was built by this repository's release workflow:

```bash
gh attestation verify konet_0.6.0_linux_amd64.tar.gz --repo raucheacho/konet
```

Or build from source:

```bash
cd konet-cli
go build -o konet .
```

## Commands

### `konet init`

Creates `konet.config.toml` in the current directory with a default config and a
generated `secret_key_base`. Edit it to set a strong `jwt_secret`, then run
`konet keys generate`.

```bash
konet init
```

### `konet start`

Pulls the server image (if missing) and starts the container.

```bash
konet start
```

### `konet stop`

Stops and removes the running container.

```bash
konet stop
```

### `konet status`

Shows container state, port mapping, and uptime.

```bash
konet status
```

### `konet logs`

Streams server logs. Prints the current buffer and exits, or pass `-f` to follow.

```bash
konet logs        # print current logs
konet logs -f     # follow (until Ctrl+C)
```

### `konet studio`

Opens the Studio dashboard in your default browser.

```bash
konet studio
```

### `konet channels list`

Lists active channel topics and subscriber counts.

```bash
konet channels list
```

### `konet publish <channel> <payload>`

Broadcasts a JSON message to a channel from the CLI. `<payload>` must be valid
JSON; the event name defaults to `message` and can be set with `-e/--event`.

```bash
konet publish lobby '{"text":"Server rebooted"}'
konet publish lobby '{"text":"hi"}' --event notification
```

### `konet keys generate`

Generates `anon_key` and `service_key` from your `jwt_secret` and writes them
back to `konet.config.toml`.

```bash
konet keys generate
```

### `konet upgrade`

Upgrades the **CLI binary** itself, depending on how it was installed:

- **Homebrew or Scoop**: prints `brew upgrade --cask konet` or
  `scoop update konet` and does nothing else — only that manager should replace
  its own binary.
- **Install script or a hand-extracted archive**: checks the latest GitHub
  release and, if you are behind, re-runs the install script, then pulls
  `ghcr.io/raucheacho/konet:latest`.
- **Windows outside Scoop**: prints the release URL instead of self-updating.

```bash
konet upgrade
```

Otherwise the server image is not updated for you: `konet start` only pulls
`ghcr.io/raucheacho/konet:latest` when no copy is cached locally, so moving the
server to a newer build is an explicit step:

```bash
konet stop
docker pull ghcr.io/raucheacho/konet:latest
konet start
```

Commands that talk to a running server (`init`, `keys`, `channels`, `publish`,
`logs`, `status`, `studio`) read `konet.config.toml` from the current directory.

## Global Flags

| Flag | Description |
|------|-------------|
| `--version` | Print the CLI version |
| `-h, --help` | Show help for any command |
