# Configuration

The server is configured entirely through environment variables. The CLI's
`konet.config.toml` is a local-development convenience that maps onto the same
variables when it starts the container.

## Environment Variables

### Core

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `MIX_ENV` | No | `prod` | Elixir environment |
| `PHX_SERVER` | No | `true` | Start the web server |
| `KONET_HOST` | No | `localhost` | Public hostname used in generated URLs |
| `KONET_PORT` | No | `4000` | HTTP port |
| `SECRET_KEY_BASE` | **Yes** | — | 64-char Phoenix secret (cookies/sessions) |

### Security

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `KONET_JWT_SECRET` | **Yes** | — | HMAC secret every token is signed with |
| `KONET_ANON_KEY` | No | — | Pre-generated anonymous token |
| `KONET_SERVICE_KEY` | No | — | Pre-generated service/admin token |
| `KONET_STUDIO_PASSWORD` | **Yes** with `docker-compose.yml` | unset | Password for `/studio`. Unset = no login: the server warns at boot and the Keys page hides the service key and secret and refuses rotation, but the rest of the Studio is open. Fine for local dev only |
| `KONET_SECRET_FILE` | No | unset (`/data/jwt_secret` in `docker-compose.yml`) | File a secret rotated from the Studio is written to (mode 0600) and read back at boot, taking precedence over `KONET_JWT_SECRET`. Put it on a volume. Unset = a rotation is lost on restart |
| `KONET_TRUST_PROXY_HEADERS` | No | `false` | Read the client IP from `X-Forwarded-For` for the per-IP connection limit. Set it only behind a reverse proxy; without a proxy, clients could forge the header |
| `KONET_ALLOWED_ORIGINS` | No | `*` | WebSocket origin check: `*` accepts any origin; otherwise a comma-separated list (`https://app.example.com,https://admin.example.com`) |

### Limits

| Variable | Default | Description |
|----------|---------|-------------|
| `KONET_RATE_LIMIT` | `60` | Max broadcasts per second per socket |
| `KONET_RATE_LIMIT_BINARY` | `120` | Max binary frames per second per socket. Separate from the message budget because binary arrives at a media rate — 20 ms audio frames are 50 per second on their own |
| `KONET_FLOOR_MAX_HOLD_MS` | `30000` | How long one client may hold a topic's floor before it is swept. Guards against a client that takes the floor and never releases it |
| `KONET_CONN_RATE_LIMIT` | `200` | Max new connections per minute per IP |
| `KONET_MULTIPLEX_MAX_MEMBERS` | `16` | Max members of one `multiplex` topic; a joiner beyond it is refused with `topic_full`. Every member may send and the server relays *n × (n − 1)* streams, so this bounds what one topic can cost the node. `0` removes the ceiling |

### Features

| Variable | Default | Description |
|----------|---------|-------------|
| `KONET_HISTORY_LIMIT` | `0` | Keep the last N broadcasts per room and replay them to late joiners as a `konet:history` event. `0` disables. In-memory only — cleared on restart |
| `KONET_HISTORY_TTL` | `900` | Seconds a room's replay buffer outlives its last message |
| `KONET_LOG_BROADCASTS` | `true` | Log every accepted broadcast to the Studio Logs page. `false` for high-throughput deployments; join/leave and floor entries are kept |
| `KONET_WEBHOOK_URL` | unset | POST `channel_occupied`, `channel_vacated`, `member_joined`, `member_left`, `floor_acquired`, `floor_released` events to this URL |
| `KONET_WEBHOOK_SECRET` | unset | If set, webhook requests carry `x-konet-signature: sha256=<hex>` (HMAC-SHA256 of the body) |
| `KONET_WEBHOOK_RETRIES` | `3` | Total attempts per event for a 5xx, 408, 429 or network error (backoff 500 ms, 1 s, 2 s…). `1` disables retrying |
| `KONET_WEBHOOK_CONCURRENCY` | `50` | Deliveries in flight at once. Beyond it an event is dropped and logged rather than queued; a pending retry does not count |

## konet.config.toml (CLI, local dev)

`konet init` generates this file; `konet start` maps it onto the env vars above:

```toml
[server]
host = "localhost"
port = 4000
mode = "docker"

[auth]
anon_key = "..."
service_key = "..."
jwt_secret = "..."
secret_key_base = "..."   # generated once by `konet init`, then stable

[studio]
password = ""             # empty = no Studio login in local dev
```

## Generating Secrets

```bash
# Phoenix secret_key_base
openssl rand -hex 32

# JWT secret
openssl rand -hex 32
```

## Webhook Payloads

```json
{
  "event": "member_joined",
  "data": { "room": "demo", "user": "alice" },
  "timestamp": "2026-07-22T16:00:00Z"
}
```

Verify authenticity by computing `HMAC-SHA256(body, KONET_WEBHOOK_SECRET)` and
comparing it to the hex value in the `x-konet-signature` header
(`sha256=<hex>`). Delivery is fire-and-forget: failures are logged on the
server and not retried.

## Monitoring

`GET /metrics` (service-key Bearer auth) exposes Prometheus text format:
connections, active channels, messages total, messages/sec, uptime. Point a
Prometheus scrape job at it with `bearer_token` set to your service key.
`GET /api/metrics` returns the same numbers as JSON.

## Production Checklist

- [ ] Set strong `SECRET_KEY_BASE` and `KONET_JWT_SECRET`
- [ ] Set `KONET_STUDIO_PASSWORD` (`docker-compose.yml` requires it)
- [ ] Keep `KONET_SECRET_FILE` on a volume, so a Studio rotation survives restarts
- [ ] Restrict `KONET_ALLOWED_ORIGINS` to your app's domains
- [ ] Run behind a reverse proxy (Nginx, Traefik, Caddy) with TLS
- [ ] Point Prometheus (or any scraper) at `/metrics`
